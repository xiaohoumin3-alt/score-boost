## 实施步骤

### Step 1: 修复 shared 模块复制逻辑

**文件**: `deploy-cloud-functions.js:48-72`

**根因**: `copySharedModules()` 只复制 `shared/` 根级 `.js` 文件和 `llm-core/` 子目录。`extendedAssessment` 依赖 `../shared/utils/irt-engine`，但 `utils/` 目录不在复制范围内，部署后 `require()` 会报 MODULE_NOT_FOUND。

**改动**: 将 `copySharedModules()` 改为使用 `copyDirRecursive(sharedDir, sharedTarget)` 统一递归复制。同时需在 `copyDirRecursive` 中增加排除 `__tests__` 目录（当前只排除了 `node_modules`/`coverage`/`tests`，但 `shared/__tests__/` 存在大量测试文件不应部署）。

```javascript
// 改后
function copySharedModules(funcDir) {
  const sharedTarget = path.join(funcDir, 'shared');
  if (!fs.existsSync(sharedTarget)) {
    fs.mkdirSync(sharedTarget, { recursive: true });
  }
  copyDirRecursive(sharedDir, sharedTarget);
}

// copyDirRecursive 排除条件增加 __tests__
if (entry.isDirectory()) {
  if (['node_modules', 'coverage', 'tests', '__tests__'].includes(entry.name)) continue;
  // ...
}
```

**验证**: `ls cloudfunctions/extendedAssessment/shared/utils/` 应包含 `irt-engine.js`。

**文件**: `cloudbaserc.json`

**改动**: 在 `functions` 数组中添加：

```json
{
```

选择理由：

- timeout 60s（submitPhase1Answers 有数据库查询 + IRT 计算，但无 LLM 调用）
- memorySize 256MB（IRT 计算轻量，不需要 512MB）
